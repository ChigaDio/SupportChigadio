# Scenario Lua DSL Editor (VSCode拡張)

Web版シナリオエディタの「全体編集(全Sub一括)」「Sub編集(現在のSubのみ)」と
**全く同じLua風テキストDSL・全く同じルール**で、VSCodeから直接シナリオイベントの
Transactionを編集・保存できるようにする拡張機能です。

DSLのコア実装(`src/dslCore.js`)は `scenarioTransactionDsl.js` をそのまま移植した
ものなので、Web版とVSCode版で解釈・見出し記法・エラーメッセージが食い違うことは
ありません（今後Web版のDSL仕様が変わった場合は、`scenarioTransactionDsl.js` の
差分をこの `dslCore.js` にも反映してください）。

## できること

- 左のアクティビティバー（Explorer/検索/ソース管理などが並ぶ、一番左の縦アイコン列）に
  **Scenario Lua のアイコン**が追加されます。クリックすると、サイドバーに
  **検索・ソート可能なグリッド(表)が常に表示された状態**で開きます。
  **コマンドを打つ必要はありません** — アイコンをクリックするだけです。
  - 列: Event ID / Event名 / Sub(またはイベントごとの「▶ 全Sub一括」行) / Sub名 / 編集ボタン
  - 上部の検索ボックスで、イベントID・イベント名・Sub ID・Sub名を横断してその場でフィルタ
  - 列見出しをクリックするとその列でソート（もう一度クリックで昇順/降順切り替え）
  - 既に編集中(開いている)行には「編集中」バッジが付きます
  - 各行の「編集」ボタンを押すと、そのSub（または「▶ 全Sub一括」行ならそのイベントの
    全Sub）を仮想ファイルとしてエディタで開きます
  - サイドバーは幅が狭いので、Event名/Sub名の列は自動で非表示になります（Event ID・Sub・
    編集ボタンだけの省スペース表示）。ビュー右上のボタンから、同じグリッドを
    大きなタブとして開くこともできます（列が全部見えて操作しやすくなります）
  - タイトルバーの「再取得」ボタン、またはビュー右上のアイコンでイベント一覧を再読み込み
- 開いた仮想ファイルでは：
  - Role名 → フィールド名 → 値、の順にカスケードで自動補完
  - 入力中にRole/フィールド/値の誤りをリアルタイムに赤波線で表示
- 通常通り **Ctrl+S (Cmd+S)** で保存
  - 保存時にDSLをコンパイル・検証し、問題なければ変更のあったSubだけを
    サーバーへ送信します
  - エラーがある場合は保存されず、出力パネル「Scenario Lua DSL」にエラー内容が
    表示されます（Web版と同じく、間違った内容のまま保存されることはありません）
- コマンド **「Scenario Lua: サーバーから最新の内容を再取得」** で、開いている
  ドキュメントをサーバー側の最新状態に更新できます
- 設定 `scenarioLuaDsl.allowCreateNewGroups`（既定OFF）
  - Web版の「新しいグループの追加を許可する」チェックボックスと同じ役割です。
  - OFFの間は、見出し(`# ==== SUB:x NODE:y ====`)に対応する既存ノードが無くても
    新しいノードは自動作成されず、警告として保存がブロックされます。
  - 新しいグループを意図的に追加したいときだけ、コマンド
    **「Scenario Lua: 新しいグループの追加を許可する/しない を切り替え」**で
    ONにしてから見出しを書き足してください。
  - `# 例: ...` で始まる案内・記入例コメントは、Web版と同様に常に無視されるため、
    消し忘れて保存してもグループが増えたり内容が化けたりすることはありません。

## セットアップ

1. `npm install` は不要です（外部npm依存なしの素のNode.js標準ライブラリのみで
   実装しています。REST通信もNode標準の `http`/`https` モジュールで行っています）。
2. VSCodeの設定で `scenarioLuaDsl.apiBaseUrl` を、シナリオ編集バックエンド
   (`scenario.py` が動いているサーバー)のベースURLに設定してください。
   例: `"scenarioLuaDsl.apiBaseUrl": "http://localhost:5000"`
3. `F5`（拡張機能開発ホストの起動）でこのフォルダを開いたまま実行するか、
   `vsce package` で `.vsix` を作成してインストールしてください。
   （`.vscode/launch.json` を同梱済みなので、F5は追加設定なしでそのまま動きます）

## トラブルシューティング

- **F5を押すと「デバッグ環境がありません」等、的外れなエラーが出る**
  → `scenario-lua-dsl` フォルダ（`package.json` がある階層）そのものをVSCodeの
  ウィンドウで開いているか確認してください。1つ上の階層（zipを展開しただけの
  親フォルダ）を開いていると、`.vscode/launch.json` が認識されず、開いている
  ファイルの種類から推測しようとして無関係なエラーが出ます。
- **イベント一覧の取得に失敗しました、と出る**
  → `scenarioLuaDsl.apiBaseUrl` の設定ミス、またはバックエンドサーバーが
  起動していない可能性が高いです。ブラウザで `{apiBaseUrl}/api/scenario-event`
  に直接アクセスしてJSONが返ってくるか確認してみてください。

## 前提にしているAPI

Web版のScenarioEventTransition.jsが使っているものと同じエンドポイントです。
バックエンドのパスがこれと異なる場合は `src/api.js` を書き換えてください。

| メソッド | パス | 用途 |
| --- | --- | --- |
| GET | `/api/scenario-event` | イベント一覧（各要素に `id`, `subEvents: [{subId, ...}]` を含む） |
| GET | `/api/scenario-role` | Role一覧（各要素に `name` を含む） |
| GET | `/api/role-form-schema/:roleName` | 1つのRoleのフィールドスキーマ |
| GET | `/api/scenario-event/:eventId/sub/:subId/transition` | 1つのSubのノードツリー `{nodes, edges}` |
| POST | `/api/scenario-event/:eventId/sub/:subId/transition` | 1つのSubのノードツリーを保存 |

## 既知の制限・今後の改善余地

- Role一覧の全スキーマを開いたタイミングでまとめて取得するため、Roleの数が
  非常に多いプロジェクトでは初回読み込みに時間がかかることがあります。
  必要であれば `src/extension.js` の `buildSession` を、実際に使われている
  Role名だけを遅延取得する方式に変更してください。
- 「未知の見出しです」等、見出し単位のエラーは行番号までは特定せず、出力パネルへの
  一覧表示のみ行っています（Role名・フィールド名・値の構文エラーは、通常のエディタ
  リンターとして行単位の赤波線で表示されます）。
